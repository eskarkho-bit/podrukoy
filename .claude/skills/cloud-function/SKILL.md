# Cloud Function

## Доставка минимум один раз

Триггер Firestore, вебхук провайдера, задача по расписанию — всё это приезжает
как минимум однажды, а иногда дважды. Повтор не должен создавать вторую
сущность и не должен возвращать деньги дважды.

Как это сделано здесь — повторяйте, а не изобретайте заново:

- **Детерминированный ключ идемпотентности.** `refund-${paymentId}`,
  `bind-${uid}-${attempt}`. В `functions/src/payments.ts:73` стоит комментарий о
  том, чем это кончилось в прошлый раз: там был `randomUUID()`, и штатная
  повторная доставка вебхука выполняла второй возврат.
- **Отметка в базе.** Перед возвратом проверяется `refundedPaymentId`
  (`payments.ts:123`) — рубеж на случай, если ключ не спас.
- **Транзакция** там, где решение зависит от текущего состояния документа.

Возврат денег защищён тремя рубежами сразу (`payments.ts:109`). Это не
избыточность: цена ошибки здесь — чужие деньги.

## Ответ вебхуку

`500` заставляет провайдера повторить попытку позже, `200` — забыть. Отвечать
`200` на необработанное событие значит потерять его молча; отвечать `500` на
то, что уже обработано, — получить бесконечный повтор. Смотрите
`payments.ts:390` целиком, прежде чем менять коды.

## Журнал

`audit()` из `functions/src/audit.ts`. Три свойства, которые делают его
журналом: append-only (пишет только Admin SDK), без персональных данных,
`correlationId` связывает цепочку одного прогона.

- Новое действие — новый вариант в `AuditAction`, не свободная строка.
- В `details` только идентификаторы, числа и перечисления. Причина отказа
  модератора и любой другой свободный текст туда не идут.
- `audit()` никогда не бросает: сбой журналирования не должен ронять то
  действие, которое журналируется.
- Фоновые операции — `actor: SYSTEM`. За ними человека нет.

## Правил доступа здесь нет

Admin SDK обходит `firestore.rules` полностью. Всё, что на клиенте защищено
правилом, в функции нужно проверять руками — и проверка не покрыта тестами
правил, потому что эмулятор проверяет клиентский путь, а не серверный.

## Проверка

```bash
npm --prefix functions run build
```

Тестов у функций нет вовсе — это единственная автоматическая проверка. Значит
изменение проверяется чтением и, для чего-то серьёзного, эмулятором вручную.

Выкатка отдельная от правил и от приложения:

```bash
npm --prefix functions run deploy
```

## Мелочь, о которую спотыкаются

`expiresAt` в журнале проставляется всегда, но TTL-политики в
`firestore.indexes.json` нет: её деплой требует включённого биллинга и падает с
403. Пока Blaze не подключён, записи копятся, и это ожидаемо. Как подключите —
вернуть запись из комментария в `audit.ts`.
