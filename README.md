# domio

Мобильное приложение для вызова мастера на дом. Клиент тыкает в объект на
изометрическом плане своего дома — розетку, мойку, окно — и описывает, что
случилось. Мастера рядом присылают цену, клиент выбирает.

Expo SDK 54 · React Native 0.81 · TypeScript · Firebase (Auth, Firestore,
Storage, Cloud Functions).

Устройство системы и объяснение принятых решений — в
[`ARCHITECTURE.md`](ARCHITECTURE.md). Правила работы с кодом —
в [`AGENTS.md`](AGENTS.md).

## Что нужно установить

| Что                    | Версия           | Зачем                                |
| ---------------------- | ---------------- | ------------------------------------ |
| Node.js                | 20 или новее     | приложение и функции                 |
| JDK                    | **21 или новее** | эмулятор Firestore для тестов правил |
| Expo Go либо dev build | —                | запуск на телефоне                   |

JDK нужен именно 21: `firebase-tools` не работает со старыми версиями, а
Java 8 в системе от этого не помогает. Проверить: `java -version`.

## Первый запуск

```bash
npm install
cd functions && npm install && cd ..
npm start
```

Дальше — QR-код в Expo Go, либо `npm run android` / `npm run ios` /
`npm run web`.

**Веб-версия работает, но не всё:** push-уведомления и камера в браузере
недоступны, привязка карты открывает страницу банка во вкладке. Для проверки
уведомлений нужен dev build на реальном устройстве — в симуляторе токен не
выдаётся в принципе.

## Конфигурация

**Клиент.** Ключи Firebase лежат в `firebaseConfig.ts` прямо в коде — так и
задумано: для веб-конфига Firebase это публичные значения, доступ ограничивают
правила, а не секретность ключа.

**Функции.** Ключи платёжного провайдера — в `functions/.env`, файл в git не
попадает. Образец: [`functions/.env.example`](functions/.env.example).

```
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
```

Пока переменных нет, привязка карты честно отвечает «не настроено», а
остальное приложение работает.

## Деплой

Порядок важен: правила и код должны выкатываться вместе, иначе новый клиент
упрётся в старые права.

```bash
npm run rules:deploy                      # правила Firestore и индексы
npm run storage:deploy                    # правила Storage, отдельно (см. ниже)
cd functions && npm install && cd ..
firebase deploy --only functions          # 12 функций
eas update --channel production           # JS-обновление приложения
```

Правила Firestore и Storage выкатываются **раздельно** намеренно: Firebase
готовит все цели одним заходом, и если Storage в проекте не подключён, падение
на нём отменяет выкатку правил Firestore тоже. Разделение позволяет закрыть
доступ к данным, не дожидаясь настройки хранилища.

Сборка в сторы — через EAS: профили `development`, `preview`, `production`
в [`eas.json`](eas.json).

### Что должно быть настроено в проекте Firebase

Без этого часть приложения не работает, и по коду это не видно:

- **тариф Blaze** — на бесплатном Spark функции не разворачиваются;
- **Cloud Scheduler API** — иначе не поднимется `reconcile`;
- **документ `admins/{uid}`** — заводится вручную в консоли, из приложения
  роль модератора выдать нельзя. Без него никто не может одобрить ни одного
  мастера, а без одобренных мастеров лента заявок пуста;
- **TTL-политика** на `audit.expiresAt` — автоудаление старых записей журнала.
  Требует биллинга, поэтому убрана из `firestore.indexes.json`: без неё деплой
  индексов падает с 403 на бесплатном тарифе. После подключения Blaze вернуть
  в `fieldOverrides` и выкатить заново:

  ```json
  { "collectionGroup": "audit", "fieldPath": "expiresAt", "ttl": true, "indexes": [] }
  ```

## Роли

| Роль               | Как получается                    | Что может                                             |
| ------------------ | --------------------------------- | ----------------------------------------------------- |
| Клиент             | регистрация                       | создавать заявки, выбирать мастера, оценивать         |
| Мастер             | анкета `masters/{uid}`            | ничего, пока не проверен                              |
| Проверенный мастер | одобрение модератора              | видит заявки своего города и профиля, предлагает цену |
| Модератор          | документ `admins/{uid}` в консоли | проверяет анкеты, читает журнал действий              |

## Диагностика

**«Недостаточно прав» на любом действии.** Правила в бою старше кода.
Проверить: `npm run rules:check`. Починить: `npm run rules:deploy`.

**Лента мастера пуста.** Либо анкета не одобрена (это норма — так и задумано),
либо в анкете указаны город и специальности, под которые заявок нет, либо не
построены составные индексы.

**Заявку нельзя отправить на проверку.** Нужна фотография лица. Карта
обязательна, но её отсутствие отправку не блокирует — решает модератор.

**Уведомления не приходят.** Функции не развёрнуты, либо тестируется в Expo Go
(удалённые push там не работают с SDK 53), либо в симуляторе.

**Эмулятор не стартует.** JDK старше 21. `java -version`, при
необходимости задать `JAVA_HOME` на нужную установку.
