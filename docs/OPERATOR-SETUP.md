# Регистрация оператора: пошаговый план

ИП, а не ООО — обоснование в [LEGAL-ANALYSIS.md](LEGAL-ANALYSIS.md), раздел 4.
Всё ниже — подготовка; сами действия делает основатель лично (регистрация
и подписи — не то, что можно поручить).

## Шаг 1. Регистрация ИП (3–5 рабочих дней)

Проще всего — через сервис ФНС «Государственная онлайн-регистрация бизнеса»
или через банк (Точка, Тинькофф, Сбер регистрируют бесплатно и сразу
открывают счёт). Госпошлины при электронной подаче нет.

**Коды ОКВЭД** (предложение, юристу/бухгалтеру можно скорректировать):

| Код   | Что                                                         | Роль                               |
| ----- | ----------------------------------------------------------- | ---------------------------------- |
| 63.12 | Деятельность web-порталов                                   | **основной** — это и есть площадка |
| 62.01 | Разработка компьютерного ПО                                 | разработка приложения              |
| 63.11 | Обработка данных, размещение и связанная деятельность       | хостинг данных пользователей       |
| 74.90 | Прочая профессиональная, научная и техническая деятельность | подбор исполнителей                |
| 82.99 | Прочая вспомогательная деятельность для бизнеса             | проверка анкет, модерация          |

**Налоговый режим: УСН «доходы» 6%.** Уведомление о переходе (форма
26.2-1) — вместе с документами на регистрацию или в течение 30 дней после.
Пока выручки нет, платятся только фиксированные страховые взносы ИП
(десятки тысяч ₽ в год — уточнить актуальную сумму на год регистрации);
взносы уменьшают будущий налог УСН до нуля.

## Шаг 2. Сразу после регистрации

1. **Расчётный счёт** — если не открыт банком при регистрации.
2. **Реквизиты в документы сервиса** — в `components/legal.ts` заполнить
   две константы: `OPERATOR` (ФИО ИП, ОГРНИП, ИНН, адрес для корреспонденции)
   и `CONTACT` (email для обращений — завести отдельный, например
   support@…, а не личный). Поднять `version` всех трёх документов на дату
   правки, прогнать `npm test` (тест «места для реквизитов ещё не
   заполнены» намеренно упадёт — обновить его, как там и написано).
3. **Перегенерировать веб-страницы документов**: `node scripts/legal-site.mjs`,
   выложить (см. шаг 4).
4. **Госуслуги для ИП** — подтверждённая учётка нужна для подачи в РКН.

## Шаг 3. ЮKassa (для привязки карт мастеров)

1. Заявка на подключение магазина на yookassa.ru (нужны ИП + счёт).
   Модерация обычно 1–3 дня. Тип интеграции — API.
2. Из личного кабинета: `SHOP_ID` и секретный ключ → в Secret Manager
   проекта Firebase (не в `.env` — см. README и RELEASE-PLAN, этап 2).
3. В настройках магазина указать URL вебхука `yookassaWebhook` (появится
   после деплоя функций) и включить события `payment.succeeded`,
   `payment.canceled`, `refund.succeeded`.

## Шаг 4. Публичная страница политики

App Store требует публичный URL политики конфиденциальности. Страницы
генерируются из тех же текстов, что показывает приложение (единый
источник — `components/legal.ts`):

```bash
node scripts/legal-site.mjs
firebase deploy --only hosting
```

Адрес после первого деплоя: `https://domio-7ad1c.web.app` (или свой домен,
когда появится). Его же указывать в App Store Connect и в уведомлении РКН.

## Шаг 5. Роскомнадзор

По черновикам из [RKN-NOTIFICATION.md](RKN-NOTIFICATION.md):
уведомление об обработке ПД, затем уведомление о трансграничной передаче.
Обе подачи — до первого живого пользователя; по США дождаться, что за
10 рабочих дней не пришёл запрет.

## Чего здесь нет намеренно

- **Товарный знак «domio»** — не обязателен для запуска, но проверить
  занятость по базе Роспатента стоит до печати визиток: переименование
  после запуска дороже (мы уже переименовывались один раз).
- **Согласие на рекламные рассылки** — пока рассылок нет, не собираем.
  Появятся промо-пуши — отдельная галочка в профиле (ст. 18 закона
  «О рекламе») и маркировка, если реклама третьих лиц.
