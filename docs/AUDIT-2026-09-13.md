# Аудит 13.09.2026: баги, лаги, уязвимости

Полный проход по ветке `feature/marketplace-and-verification` тремя
независимыми проверками — безопасность (правила доступа, функции,
хранилище), ошибки в логике (все три роли: клиент, мастер, модератор) и
скорость (подписки, перерисовки, анимации, размер сборки). Ниже — что нашли,
что закрыли и что осталось. Всё закрытое выкачено в бой 13.09: правила
Firestore и Storage, 22 функции, OTA-обновление приложения в канал `preview`.

## Как проверяли

- Три независимых обзора кода по ролям и слоям; каждая находка сверена с
  кодом и правилами вручную, спорные — проверены на эмуляторе.
- Замеры: JS-сборка 7,9 МБ байткода (React Native 2,4 МБ, Firestore 1,2,
  Reanimated 0,8, Sentry 1,7 — пока не подключён, код приложения 0,7);
  `npm audit` — 13 «high», все в инструментах сборки, в приложение не
  попадают; консоль приложения на эмуляторе без предупреждений; все запросы
  админки покрыты индексами.
- Проверено на эмуляторе Auth: после входа по custom-токену в ID-токене есть
  `phone_number` — на этом стоит новое правило «телефон в профиле только свой».

### Ошибки (17 находок, 16 закрыты)

- Анкета мастера открывалась пустой после перезапуска: форма заполнялась до
  прихода данных. Теперь до первого чтения — индикатор.
- Отзыв согласия у проверенного мастера: файл удалялся, а правила отклоняли
  переход. Правила пускают отзыв из `approved` и `pending`; порядок —
  сначала документ, потом файл.
- Бейдж непрочитанных не возвращался после первого открытия чата:
  запоминается последнее увиденное сообщение, а не факт открытия; ответ,
  пришедший в открытый чат, считается прочитанным.
- Токен устройства не убирался при выходе: теперь убирается — после выхода
  чужие уведомления на телефон не приходят.
- Вход по свободному номеру сжигал код: теперь код действует, приложение
  сразу показывает поля регистрации.
- Почтовая регистрация могла создать профиль «Гость»: имя передаётся в
  черновик регистрации и для почты.
- Удаление клиента оставляло заявку «Ждёт подтверждения» навсегда:
  засчитывается мастеру как завершённая.
- Возвращённая в поиск заявка не объявлялась мастерам заново: объявляется,
  отказавшийся исключён.
- Повтор заявки звал заблокированного мастера: не зовёт; сервер проверяет
  то же.
- «Правила не обновлены — нужен firebase deploy» показывалось
  пользователям: подсказки про деплой и индексы остались только в
  отладочной сборке.
- Отстранённый мастер видел старую ленту из памяти: лента сбрасывается.
- Открытая заявка, исчезнувшая из списка, оставалась открытой: закрывается.
- «Работа выполнена» уходило в чат даже при неудачной отметке: только после
  успеха.
- Заявка без города рассылалась всем мастерам, хотя в ленте её видели только
  мастера без привязки к городу: теперь рассылка совпадает с лентой.
- Лента мастера пересоздавала подписки на каждое обновление рейтинга:
  зависимости — примитивы.
- Мелкое: откат имени при неудачной блокировке, двойное сохранение имени в
  профиле, комментарий об отзывах в удалении расходился с кодом.
- Не закрыто: индикатор «клиент печатает» у мастера не имеет источника
  (задокументированный долг — писать в Firestore на каждое нажатие дорого).

### Скорость (дешёвые правки сделаны)

- Значение темы мемоизировано: раньше каждый компонент с `useTheme()`
  перерисовывался на каждое событие Firestore.
- Ключи подписок на переписку и предложения отсортированы: новая заявка
  больше не пересоздаёт все подписки дважды.
- Размытие под шторками на Android выключено (`components/blur.ts`): там
  оно делало снимок экрана каждый кадр.
- Ступенчатое появление списков ограничено восемью шагами; `onScroll` — не
  чаще десяти раз в секунду; скрытые вкладки заморожены (`freezeOnBlur`).
- Закрытый раздел мастера не рисуется: подписки живут, невидимая лента не
  перерисовывается на каждое событие.
- Функция трансформа заставки не пересоздаётся на каждый рендер.

## Что осталось (по убыванию пользы)

1. **Списки на `ScrollView` + `map`** (заявки, лента мастера, переписка).
   На сотне карточек это заметно; перевод на `FlatList`/`FlashList` — день
   работы. Делать, когда у мастеров появятся десятки заявок в ленте.
2. **Подписка на переписку каждой заявки** — N слушателей у клиента с N
   заявками. Заменить одной подпиской по группе коллекций с фильтром по
   участнику потребует поля `participants` в сообщениях и миграции.
3. **Изображения без ресайза** — `expo-image` с кешем и `contentFit` вместо
   `Image`; в Storage — уменьшение на клиенте перед загрузкой (сейчас до
   10 МБ за файл).
4. **Дом на главном экране**: холостые циклы анимации и SVG заставки —
   ощутимо на слабых Android. Остановить циклы, когда экран не виден.
5. **Sentry** — 1,7 МБ в сборке уже лежат, аккаунта нет; после подключения
   вернуть загрузку source maps (см. RELEASE-PLAN, этап 4а).
6. Демо-стенд на эмуляторе Storage: ссылки `http://127.0.0.1:9199/...`
   правила теперь не пускают — снимки на стенде сеются админ-скриптом, а
   загрузка из приложения на стенде не пройдёт. В бою это не проявляется.

## Что проверить владельцу на телефоне

1. Открыть раздел «Я мастер» после холодного запуска — анкета заполнена.
2. Открыть чат, получить ответ, вернуться — бейдж есть; открыть снова —
   бейдж исчез; новый ответ — бейдж вернулся.
3. Выйти из аккаунта — пуши на этот телефон больше не приходят.
4. Вход по незарегистрированному номеру — форма сразу переключается на
   регистрацию, код действует.
5. Отменить заявку в работе — чат читается, поле ввода закрыто.
