# Правила работы с этим проектом

## Версия Expo

В проекте стоит **Expo SDK 54**, а не 57. Документация к нему:
https://docs.expo.dev/versions/v54.0.0/

Раньше здесь стояла ссылка на v57 — API там другой, и код по ней не
собирается. Проверяйте версию в `package.json`, а не по памяти.

## Перед изменениями

Прочитайте `ARCHITECTURE.md`. Там объяснено не только устройство, но и
**почему** принято каждое решение и что было отвергнуто. Половина здешних
странностей — следствие ограничений Firestore, а не небрежности.

## Обязательные проверки

Любое изменение должно проходить всё семь, иначе оно не готово:

```bash
npx tsc --noEmit                 # типы приложения
cd functions && npm run build    # типы функций
npm run lint                     # eslint
npm run format:check             # prettier
npm test                         # 106 тестов компонентов
npm run test:rules               # 117 тестов правил доступа, нужен JDK 21
npm --prefix functions test      # 76 тестов функций, нужен JDK 21
```

Правила Firestore — единственное, что стоит между пользователями и чужими
адресами. Меняете `firestore.rules` — меняете и тесты.

Тесты функций держат то, что ломается тихо: повтор вебхука не делает второй
возврат, обрыв удаления аккаунта возобновляется с места обрыва, два прогона
сверки не идут одновременно. Провайдер там подменён, Firestore настоящий.
Последние два шага поднимают эмулятор на одном и том же порту — по очереди.

Линтер разбирает `functions/` вместе с типами: без этого `no-floating-promises`
не находит забытый `await`. Поэтому `npm ci` в `functions/` нужен и для линтера,
а не только для сборки. Формат правит `npm run format`.

## Что легко сломать

- **Правила и код должны выкатываться вместе.** `npm run rules:check`
  показывает, не отстали ли правила в бою от репозитория.
- **Составные индексы.** Новый запрос с двумя условиями требует записи в
  `firestore.indexes.json`, иначе он падает в рантайме, а не при сборке.
- **Идемпотентность.** Всё, что делают функции, доставляется минимум один
  раз — иногда дважды. Повтор не должен создавать вторую сущность и не
  должен возвращать деньги дважды.
- **Персональные данные в журнале.** В `audit` кладут только идентификаторы
  и перечисления: журнал переживает удаление аккаунта.

## Стиль

- Комментарии на русском, объясняют «почему», а не «что».
- Строки интерфейса на русском, склонения через `components/format.ts`.
- Экраны не знают о Firestore — данные приходят через `AppState`.
  Исключение одно: `MasterScreen`, и это долг, а не образец.
